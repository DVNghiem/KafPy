```rust
/// Registers a fan-in handler: a single Python callback that receives messages
/// from multiple Kafka topics in round-robin order.
///
/// Args:
///     handler_key: Identifier for this handler (used in QueueManager).
///     sources: List of topic names to subscribe to.
///     callback: Python callable invoked for each message.
///     timeout_ms: Per-handler execution timeout in milliseconds.
///
/// Returns a `FanInRegistration` with handler_key, fan_in_id, and sources.
#[pyo3(signature = (handler_key, sources, callback, timeout_ms=None))]
pub fn register_fanin(
    &mut self,
    handler_key: String,
    sources: Vec<String>,
    callback: Bound<'_, PyAny>,
    timeout_ms: Option<u64>,
) -> PyResult<FanInRegistration> {
    use crate::python::fan_in_bridge::FanInBuilderRust;
    use std::sync::Arc;

    let mode = HandlerMode::from_opt_str(None); // sync by default for now
    let builder = FanInBuilderRust::new(
        handler_key.clone(),
        sources.clone(),
        Arc::new(callback.unbind()),
        mode,
        timeout_ms,
    );
    builder.register_into_consumer(self)
}
```

Also add `FanInRegistration` to PyO3 imports at the top of the file.
</action>

The key changes:

1. **Detect fan-in handlers**: After collecting handlers, check if any HandlerMetadata has `fan_in_id` set (meaning it's a fan-in handler). For fan-in, the `handler_key` is the key in the handlers map, and `sources` is stored in the fan_in_bridges map.

3. **Route to fan_in_worker_loop**: In `WorkerPool::new`, pass fan-in sources and fan_in_id to `fan_in_worker_loop` instead of the regular worker loop.

**Specific implementation**:

After building `handler_map` and before `WorkerPool::new`, add:
```rust
// Collect fan-in handler info: (handler_key, sources, handler, fan_in_id)
let fan_in_handlers: Vec<_> = self.fan_in_handlers.iter().map(...)
    .filter(|(_, meta)| meta.fan_in_id.is_some())
    .collect();
```

Pass `fan_in_handlers` to `WorkerPool::new` so it can spawn `fan_in_worker_loop` tasks for each fan-in group.

**D-01**: ConsumerRunner subscribe is already called in `ConsumerRunner::new` with `config.topics`. For fan-in, RuntimeBuilder should pass all fan-in source topics to the ConsumerRunner so it subscribes to them all at once.
