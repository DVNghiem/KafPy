## Fan-In Worker Loop Signature (new)

/// Fan-in worker loop — merges messages from multiple topic streams.
///
/// For each topic source, spawns a background task that receives messages from that
/// topic's Kafka partition and forwards them into a shared mpsc channel.
/// The main loop then uses tokio::select! biased to interleave messages by arrival order.
///
/// # Arguments
/// * `worker_id` — Unique worker identifier for logging
/// * `sources` — Vec of (topic, Kafka partition, message_stream) for each source
/// * `handler` — Python handler to invoke for each merged message
/// * `fan_in_id` — Fan-in group ID for ExecutionContext
/// * `queue_manager` — Queue manager for acking messages
/// * `cancel` — Cancellation token for graceful shutdown
pub async fn fan_in_worker_loop(
    worker_id: usize,
    sources: Vec<(String, i32, impl Stream<Item = OwnedMessage>)>,
    handler: Arc<PythonHandler>,
    fan_in_id: u64,
    queue_manager: Arc<QueueManager>,
    cancel: CancellationToken,
) -> Result<(), Box<dyn std::error::Error + Send + Sync>>

<action>
Create `src/worker_pool/fan_in_loop.rs` implementing the fan-in worker loop.

The loop structure:
1. For each source (topic, partition, stream), spawn a background task that pushes messages from that stream into a shared `mpsc::channel(100)` per source. This decouples Kafka consumption from the merge loop.
2. Main loop uses `tokio::select! { biased; }` to poll all source channels fairly.
3. For each received message from source S, set `ExecutionContext.source_topic = S.topic` and invoke the handler.
4. `fan_in_id` is set in ExecutionContext for all messages.

```rust
use tokio::select;
use tokio_stream::StreamExt;
use std::sync::Arc;
use tokio::sync::mpsc;

pub async fn fan_in_worker_loop(
    worker_id: usize,
    sources: Vec<(String, i32, impl Stream<Item = OwnedMessage>)>,
    handler: Arc<PythonHandler>,
    fan_in_id: u64,
    queue_manager: Arc<QueueManager>,
    cancel: CancellationToken,
) -> Result<(), Box<dyn std::error::Error + Send + Sync>> {
    // For each source, create a shared channel
    // Spawn background tasks to forward from Kafka stream to shared channel
    // Main loop: tokio::select! biased, polling each shared channel
    // For each message: set source_topic in ExecutionContext, invoke handler

    // Channel type per source: (OwnedMessage, source_topic)
    let mut source_channels: Vec<(String, mpsc::Receiver<(OwnedMessage, String)>)> = Vec::new();

    for (topic, _partition, stream) in sources {
        let (tx, rx) = mpsc::channel(100);
        source_channels.push((topic.clone(), rx));

        // Spawn forwarder task
        let topic_clone = topic.clone();
        tokio::spawn(async move {
            let mut stream = stream;
            while let Some(msg) = stream.next().await {
                if tx.send((msg, topic_clone.clone())).await.is_err() {
                    break;
                }
            }
        });
    }

    // Main merge loop
    loop {
        select! {
            biased;

            _ = cancel.cancelled() => {
                tracing::info!(worker_id = worker_id, "fan-in worker: cancellation received");
                break;
            }

            // Poll each source channel — biased makes iteration order fair
            // For each ready message, invoke handler with source_topic set
            for (topic, ref mut rx) in &mut source_channels {
                if rx.try_recv().is_ok() {
                    // Received from this source — invoke handler
                    // Build ExecutionContext with source_topic = topic
                    // Set fan_in_id = fan_in_id
                    // Call handler.invoke_mode_with_timeout()
                    // On completion, ack via queue_manager
                }
            }
        }
    }

    Ok(())
}
```

The actual handler invocation must use the same pattern as `worker_loop`:
- Build `ExecutionContext` with `worker_id`, topic (from message), partition, offset
- Set `source_topic = topic` (the topic the message arrived from)
- Set `fan_in_id = Some(fan_in_id)`
- Call `handler.invoke_mode_with_timeout(ctx, message).await`
- On `ExecutionResult::Ok`, call `queue_manager.ack(source_topic, 1)`
- On error, call `handle_execution_failure` (imported from `crate::worker_pool`)

Keep the loop structure minimal — focus on the round-robin merge pattern with source_topic tagging.
