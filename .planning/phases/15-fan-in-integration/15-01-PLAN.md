Wire per-source backpressure in the fan-in routing path. When a fan-in handler's queue is full, the backpressure signal must target the specific Kafka source topic (from message.topic) rather than the handler_key.

Per D-02: Source topic is available from ExecutionContext.source_topic (populated in Phase 14). Route on_queue_full signal to the specific topic that is slow, not the fan-in handler key.

## Key Contract

The `BackpressurePolicy::on_queue_full` trait method currently receives `handler_id: &str` (the fan-in handler_key) as the first parameter. The handler metadata is then used to look up queue depth. The policy returns `BackpressureAction::PausePartition { topic, partition }`.

**Current broken flow:**
1. `route_with_chain` gets backpressure error from `send_to_handler_by_id`
2. Calls `policy.on_queue_full(handler_id, metadata)` — passes handler_key as topic
3. `PauseOnFullPolicy::on_queue_full` returns `BackpressureAction::PausePartition { topic: handler_id, ... }`
4. Pause signal targets wrong topic (handler_key instead of source topic)

**Fixed flow:**
1. `route_with_chain` gets backpressure error from `send_to_handler_by_id`
2. Calls `policy.on_queue_full(msg.topic, metadata)` — passes the actual Kafka source topic
3. `PauseOnFullPolicy::on_queue_full` returns `BackpressureAction::PausePartition { topic: msg.topic, ... }`
4. Pause signal correctly targets the slow source topic

## Interface: BackpressurePolicy trait

```rust
// CURRENT (broken for fan-in)
pub(crate) trait BackpressurePolicy: Send + Sync {
    fn on_queue_full(&self, topic: &str, handler: &HandlerMetadata) -> BackpressureAction;
}

// FIXED (per-source backpressure via message topic)
pub(crate) trait BackpressurePolicy: Send + Sync {
    fn on_queue_full(&self, topic: &str, handler: &HandlerMetadata) -> BackpressureAction;
    // Note: 'topic' parameter now carries the actual Kafka source topic (msg.topic),
    // not the handler_id. Policy implementations use this for targeted pause.
}
```

The `topic` parameter in `on_queue_full` now carries the actual Kafka source topic from the message, enabling per-source pause. `PauseOnFullPolicy` uses this topic directly in the returned `BackpressureAction`.

```rust
/// Policy for handling backpressure when a handler queue is full.
///
/// Implementors define custom behavior when `try_send` fails with `Full`.
/// The `topic` parameter is the **actual Kafka source topic** from the message,
/// NOT the handler_id. This enables per-source targeted pause for fan-in scenarios.
pub(crate) trait BackpressurePolicy: Send + Sync {
    /// Called when a send attempt fails because the handler's queue is full.
    ///
    /// The `topic` parameter is the **source topic from the message being dispatched**,
    /// not the handler_id. Implementors can use this to route PausePartition to the
    /// specific slow source rather than the fan-in handler key.
    fn on_queue_full(&self, topic: &str, handler: &HandlerMetadata) -> BackpressureAction;
}
```
